# Readable logbook and filtered reports

The super-admin logbook shows compact clickable rows containing the administrator, section, short action summary, time in IST, affected-record count and save result. Bulk changes show a count such as “Updated 91 product records” rather than listing every product upfront. Click anywhere on a row, press Enter/Space while focused on it, or select Inspect changes to load full details. The list API excludes raw snapshots and individual change values; the detail API returns readable product/account names and before/after values. Variants and permissions expand into named fields. Passwords and authentication secrets remain hidden. Stored audit records are preserved.

MongoDB ObjectIds and Date objects are now serialized as identifier/ISO strings before presentation. This fixes invalid record IDs and “Time unavailable” caused by recursively treating those values as generic objects. Product model numbers already contained in product names are not repeated in labels.

Use From date / To date plus Time from / Time to to narrow activity. All inputs use IST independently of the browser timezone. The time window applies to each selected day: 12:00–18:00 shows noon to 6 PM on those dates, or every day if dates are blank. Boundaries include the selected minute. Overnight windows (for example 22:00–06:00) are supported. Search includes actor names/emails and recorded product names, model numbers and SKUs; section/result filters apply to list and exports alike.

Export PDF and Export Excel download readable reports containing filter context, generation time, administrators, named records and all recorded before/after changes. Reports include all matching screen pages, with up to 1,000 entries per report. Larger selections receive an explicit request to narrow filters; no partial report is silently downloaded. Both exports remain super-admin-only and redact authentication secrets. The PDF includes page numbers; the Excel file is a native editable XLSX with Activity and Changes worksheets. Activity has one row per entry; Changes has one row per individual field change. Entry numbers connect the two views. Both worksheets include the selected filter context, frozen headers, column filters and readable labels. Times are typed Excel dates displayed in IST; price and stock changes are numeric cells for sorting and analysis.

Verification covers matching filters between screen and exports, cross-page exports, invalid dates/times, BSON IDs/dates, bulk summaries, whole-row inspection, role restrictions, and generated PDF/XLSX content. Sample reports were rendered with Poppler and the bundled LibreOffice renderer and checked for page breaks, readability and footer placement. No production audit records were changed during validation.

Dealer cart summaries now use only applicable unit prices and payable totals. They display no dealer-discount breakdown or retail comparison, including in generated WhatsApp enquiry text.

## Automatic data retention

Audit logs are retained for a rolling 30 days and session records for a rolling 7 days, measured from each record's creation time. MongoDB TTL indexes perform permanent background cleanup, including existing older records after deployment. Indexes are declared on the models and explicitly ensured by the primary backend instance at startup, so retention also works when automatic model indexing is disabled. No application polling or audit-generating delete loop is used. MongoDB cleanup is asynchronous: its monitor normally runs about once per minute, and database load can delay physical deletion.

Logbook list, exports and individual-entry inspection apply the 30-day boundary immediately, even while an expired document is waiting for the TTL sweep. Session lists likewise show only the last 7 days. Customer sessions retain their shorter configured lifetime (24 hours by default); dealer and admin sessions now have a maximum 7-day lifetime. Existing legacy longer sessions are checked against the same limits before token refresh or authenticated access. Last activity does not reset the retention clock. Users sign in again after session expiry; user accounts are not deleted by this cleanup.

Deploy the updated frontend and backend to replace the Word button and install the TTL indexes. No production records were deleted during local verification. Retention indexes and expiry boundaries are covered in `tests/unit/dataRetention.test.js` and `tests/unit/sessionExpiry.test.js`. [MongoDB TTL documentation](https://www.mongodb.com/docs/manual/core/index-ttl/) describes the asynchronous deletion timing.
