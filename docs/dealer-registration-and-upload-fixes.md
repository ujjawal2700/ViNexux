# Dealer registration and profile upload fixes

Admin dealer creation/conversion now exposes the additional business and document fields without making them mandatory. The existing name, email, mobile and company requirements remain for creating a new account; conversion requires company name. GST, Aadhaar, PAN and Udyam uploads, supplementary business fields and office location are optional for these admin flows. Supplied data/files still pass validation. Customer self-service registration requirements are unchanged.

Dealer profile file buttons previously nested a button inside the file input label. Clicking that interactive button did not activate the label's hidden file picker. Dedicated controls now explicitly open their input, reset the input after selection so the same image/PDF can be retried, and prevent overlapping document operations. Profile replacement uploads the new object, saves its reference, and only then removes the old storage object. A failed database save cleans up the replacement and leaves the old storage file intact.

The state/city dropdown was behind Leaflet's controls. It now renders an opaque, viewport-positioned portal above the map, supports keyboard selection and Escape, and constrains the list to the viewport. Searches understand alternate spellings and diacritics. Chittorgarh existed in the old short Rajasthan list; its visibility, case-insensitive selection and final signup payload now have dedicated browser tests, including mobile coverage.

City options come from the official Census of India 2011 urban town workbook, accepting only `Level = TOWN` and `TRU = Urban` rows. Rural gazetteer data and population-based guesses are no longer used. Numbered settlement names, entries explicitly labelled Village and outgrowth aggregates are excluded. There are 7,692 unique state/city names across all 36 current state/UT selectors, with source town codes retained for auditing. The 2011 district codes map the later Telangana/Ladakh splits and the merged Dadra/Nagar Haveli/Daman/Diu UT. This is a dated urban directory, not a claim to include every subsequent municipal notification.

State files load on demand and are cached. Each file carries its state and urban classification; mismatched or rural files are rejected. Content-versioned requests prevent reuse of the old rural lists after deployment. Immediate fallback options are generated from the same accepted urban records. Search only filters these options; free-text additions are disabled in registration and profile editing. Changing state clears the prior city, and stale responses cannot replace the current state's list. Existing saved values remain displayed until edited; these changes do not rewrite existing profiles.

Data attribution, license, input checksum and regeneration instructions are in `frontend/public/data/india-places/README.md`. Deploy the frontend including that directory, together with the backend changes. These changes have not been deployed by this task.

Verification covers optional admin uploads, picker activation, repeated image replacement, failed-upload retry, storage/database failure cleanup, state dataset coverage, Chittorgarh/Chittaurgarh searches, Rawatbhata, dropdown visibility above the map on desktop/mobile, rejection of free-text rural additions during dataset failure and the final Chittorgarh/Rajasthan registration request. Provider and database effects are mocked in these tests.
